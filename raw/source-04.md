## 主要研究內容

為「對抗式機器學習（Adversarial Machine Learning）」建立標準分類與術語，分成預測式 AI 與生成式 AI 兩大部分。本專案只使用**生成式 AI** 中與 Prompt Injection 相關的章節（§3.3–3.5）。

## 重要結論

### 0. 背景：RAG 與 Agent [S4, §1]（2026-11-23 獨立複查後補記）

- §1 引言說明 RAG 是讓模型使用企業資料庫與文件的方式，並提到基於 LLM 的 Agent 能採取現實世界的行動。（來源：第一次讀取 PDF 時的 §1 內容，當時未寫入筆記，複查發現後補記）
- §1 另指出許多緩解方法偏經驗性質、有其侷限。

### 1. 定義：以「誰是攻擊者」來區分 [S4, §3.3–3.4]

- **直接提示攻擊（Direct Prompting Attacks）**：攻擊者就是系統的**主要使用者**，透過一般的查詢介面與模型互動。[S4, §3.3]
- **直接提示注入（Direct Prompt Injection）**：直接提示攻擊的**一種**，使用者的指令被接在應用設計者的較高信任指令（如系統提示）之後。[S4, §3.3]
- **越獄（Jailbreak）**：也是直接提示攻擊的**一種**，目的是繞過對模型輸出的限制。[S4, §3.3]
- **間接提示注入（Indirect Prompt Injection）**：攻擊者控制模型會讀取的**資源**，攻擊由**第三方**而非主要使用者發動。[S4, §3.4]

### 2. 間接注入的三類攻擊目標 [S4, §3.4.1–3.4.3]

| 目標 | 白話意思 | 例子類型 |
|---|---|---|
| 可用性（§3.4.1） | 讓系統對正常使用者「不能用」 | 強迫做耗時背景工作、擋住某些功能、破壞輸出格式 |
| 完整性（§3.4.2） | 讓系統「不可信」或被劫持任務 | 誤導性摘要、隱藏來源、污染 RAG 知識庫、自我傳播 |
| 隱私（§3.4.3） | 讓系統「洩密」 | 洩漏模型能存取的受限資料、誘騙使用者提供資訊再轉給攻擊者 |

- 間接攻擊也可能**借用越獄技巧**來取代系統提示中的指令。[S4, §3.4.2]

### 3. Agent 安全 [S4, §3.5]

- Agent 會反覆呼叫模型、處理輸出、把結果再送回去，常搭配瀏覽器、程式執行器等**工具**。
- Agent **繼承**直接與間接注入的所有風險；**工具使用再增加風險**，例如被劫持去執行任意程式碼或外洩資料。
- 報告指出 Agent 安全研究**仍在早期階段**。

### 4. 防禦方法 [S4, §3.3.3、§3.4.4]

**直接提示攻擊（§3.3.3）**：訓練階段介入（含對抗訓練）、評估（自動化評估、專家紅隊、漏洞獎勵、部署後持續評估）、提示技巧（分隔系統指令與使用者輸入）、偵測（偵測並中止有害互動）、輸入輸出處理、監控與使用限制，以及**假設注入一定會發生**來設計系統。

**間接提示注入（§3.4.4）**：
- 訓練：訓練模型遵守提示中的**階層式信任關係**
- 偵測：偵測間接注入的機制、以 LLM 作為防禦
- 輸入處理：過濾第三方來源中的指令、**聚光燈法（spotlighting，把可信與不可信資料明確區隔）**、要求模型忽略不可信資料中的指令
- 系統設計：使用**多個權限不同的 LLM**、把不可信資料限制在明確定義的介面
- 公眾教育：讓使用者與設計者了解風險

### 5. 防禦的限制

- 直接注入：報告指出現今的模型對直接提示注入仍然**高度脆弱**；偵測系統本身也可能被攻擊；評估結果可能**低估**資源更多的攻擊者能做到的事。[S4, §3.3.3]
- 間接注入：現有緩解方法無法對所有攻擊手法提供完整保護。[S4, §3.4.4]
- 整體：許多緩解方法偏向經驗性質、有其侷限，而且可能被新發現的攻擊方式破解。[S4, §1]

### ⚠️ 來源差異：越獄與 Prompt Injection 的關係

> **更新（2026-11-23）**：S1 改用 OWASP 2026 版後，OWASP 仍維持「越獄是子集」。依「以最新為主」原則，使用者決定**改採 OWASP 2026 分法**；以下 NIST 觀點保留作為另一種觀點。原先「建議採用 NIST」的段落已作廢。

> - S1（OWASP）把越獄視為 Prompt Injection 的**一種**。[S1, 描述]
> - S4（NIST）把越獄和直接提示注入**並列**，兩者都屬於「直接提示攻擊」：越獄的目標是繞過安全限制，直接注入則是把使用者指令接在較高信任的系統指令後面。[S4, §3.3]
> - S2 把越獄當作相關但不同的研究脈絡。[S2, §2]
> - 可能原因：OWASP 是給開發者的風險清單，傾向用大分類涵蓋；NIST 的目的是建立精確術語，因此依攻擊目的細分。
> - ~~（已作廢）建議採用：NIST 的分法——兩者是「近親」，常一起出現（S4 也指出間接攻擊會借用越獄技巧 [S4, §3.4.2]），但**目的不同**：越獄是讓 AI 打破安全規則，注入是讓 AI 聽錯人的指令。理由：NIST 以建立標準術語為目的，定義較精確，也較容易讓一般大眾分辨。
