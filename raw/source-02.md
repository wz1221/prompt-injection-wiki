## 主要研究內容

首篇系統性提出 **間接提示注入（Indirect Prompt Injection, IPI）** 的研究：攻擊者不必直接和 AI 對話，只要把指令放進 AI **之後會去讀取的資料**（網頁、郵件、程式碼等），就能在遠端影響**其他使用者**的 AI 應用。論文提出威脅分類，並在實際系統與自建測試應用上示範。

## 重要結論

1. **資料與指令的界線變模糊**：當 LLM 會去讀取外部資料時，處理不可信資料就像「執行」任意程式碼一樣，資料與指令的界線因此變得模糊。[S2, §1–2]
2. **直接 vs 間接的關鍵差異**：直接注入是使用者攻擊自己的對話；間接注入是**第三方**從遠端攻擊**其他使用者**。[S2, §1]
3. **注入方式分類** [S2, §3.1]：
   - 被動式：把指令放在可能被搜尋到的網頁、隱藏的網頁內容、程式碼或文件中
   - 主動式：直接寄送含指令的電子郵件給有 AI 郵件助理的人
   - 使用者驅動：誘騙使用者自己貼上含指令的文字
   - 隱藏式：多階段載入、藏在圖片中、編碼等
4. **六類威脅** [S2, §3.2]：
   - 資訊蒐集（竊取資料、洩漏對話）
   - 詐騙（釣魚、利用使用者對搜尋結果的信任）
   - 入侵（後門、持續控制、惡意程式碼建議）
   - 惡意程式（惡意連結、會自我傳播的提示詞）
   - 內容操縱（錯誤或偏頗摘要、隱藏來源、假訊息、隱藏廣告）
   - 可用性破壞（拖慢、癱瘓服務）
4b. **攻擊目標範圍** [S2, §3.2.1]（2026-11-23 獨立複查後補記）：區分不特定對象的大量攻擊與針對特定對象的攻擊，以及對自動化流程的攻擊。
5. **實際示範** [S2, §4]：在自建測試應用（以當時的 OpenAI 模型搭配模擬工具）、Bing Chat（透過 Edge 側邊欄，使用**本機**網頁測試）及 GitHub Copilot 上示範上述威脅類型。
   - 觀察：被過濾的指令若改用間接方式注入，仍可能通過；注入效果可在整段對話中持續。[S2, §4.2]
   - 包含「AI 郵件助理把注入內容轉寄給聯絡人」這種會自我傳播的情境。[S2, §4.2.3]
6. **負責任揭露**：作者已將漏洞告知 OpenAI 與 Microsoft，且**沒有**把注入內容放到其他使用者可能讀到的公開來源。[S2, §5.1]
7. **防禦與限制** [S2, §5.6]：
   - 以人類回饋強化學習（RLHF）修補可能陷入「打地鼠」模式，修一個又冒出一個。
   - 候選防禦：輸入過濾、用另一個 LLM 監督、可解釋性異常偵測，各有取捨。
   - 結論：目前很難想像有萬無一失的解決方案。
   - 觀察到當時的 Bing Chat 會過濾使用者輸入與輸出，但似乎沒有考慮外部輸入。

## 限制與注意事項（論文自述 + 筆者觀察）

- **論文自述** [S2, §5.2]：使用自建應用與本機 HTML 測試，非真實環境攻擊；無法測試 Microsoft 365 Copilot 與 ChatGPT plugins；**沒有量化攻擊成功率**。
  → Wiki 中**不得**引用本文作為「攻擊成功率」的數據來源。
- 黑箱、非確定性系統讓精確重現困難。[S2, §5.4]
- 2023 年的產品測試結果不代表現在的產品仍有相同漏洞，Wiki 與簡報中需標明「2023 年研究中」。
